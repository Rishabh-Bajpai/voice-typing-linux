## 🐛 Bug: Stale push-to-hold timer on service restart

**File:** `voice_dictation.py:720-731`  
**Severity:** Medium

`stop_service()` doesn't cancel `self._pth_timer`. If the service is stopped mid-recording, the timer keeps ticking. If the user restarts and activates push-to-hold again within 5 seconds, the old timer's callback cancels the new timer:

```
t=0  push-to-hold start, Timer A (5s) created
t=2  stop_service() — Timer A keeps ticking
t=3  start_service()
t=4  push-to-hold start, Timer B (5s) created, self._pth_timer = Timer B
t=5  Timer A fires → calls _push_to_hold_stop()
     → self._pth_timer.cancel() cancels Timer B
     → self._pth_timer = None
```

The new recording loses its 5-second safety net. If the release listener also fails (documented as unreliable), the recording gets stuck until manual intervention.

**Fix:** Add `self._pth_timer` cancellation to `stop_service()`.

## 🟡 Push-to-hold / clipboard mode state lost on restart

**File:** `voice_dictation.py:509-520`, `app.py:1040-1045`  
**Severity:** Low

`push_to_hold` and `clipboard_mode` settings are applied at runtime in `save_settings()` but never written to `config.json`. `update_config()` → `save_config()` only persists: `STT_ENDPOINT`, `STT_MODEL`, `STREAMING_MODE`, `BEEP_ENABLED`, `SILENCE_THRESHOLD`, `DEVICE_INDEX`, `HOTKEY_STR`, `SILENCE_DURATION`, `PULSE_SOURCE_NAME`.

If intentional (runtime-only session state), this is fine. If these should survive restart, they need to be added to persistence.

## 🟡 Tray menu `_sync_menu` label manipulation is fragile

**Severity:** Low

label = item.get_label().lstrip("\u2633 ")

## ℹ️ `_backspace()` spawns N subprocesses

**File:** `voice_dictation.py:385`  
**Severity:** Informational

Each backspace creates a separate `subprocess.run(["xdotool", "key", "BackSpace"])` call. "Delete last sentence" spawns 20 xdotool processes. Consider batching keys in a single `xdotool key --delay 1 BackSpace BackSpace ...` call.
